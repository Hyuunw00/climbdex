# 로드맵

## 1. 영상 자동 컷
- 입력: 사진 앱에서 영상 여러 개 선택
- 처리: 영상마다 시도 구간을 여러 개 검출. 시작 = 사람 상자가 바닥 기준선 위로 올라가는 순간, 끝 = 다시 바닥 높이로 내려오거나 화면에서 사라지는 순간
- 사용자 조절: 시작 전 N초·끝 후 N초 여유값, 구간별 시작·끝점을 미는 조절 바
- 출력: 구간마다 개별 클립으로 사진 앱에 저장
- 플랫폼: iOS 먼저. RN이면 영상 처리만 네이티브 모듈
- 시작 조건: `docs/exp-01-video-cut.md` 실험 통과

## 2. 암장 도감 (2026-09-29 착수, 서버 없이 시작)

- 목록 갱신(2026-09-29 결정): 서버 전까지 511곳 고정. 새 암장·폐업 반영은 서버 단계에서 사용자 추가·폐업 신고로 해결. 그 전엔 손대지 않음
- 나중(2026-10-01 재확인: **사용자가 어느 정도 생긴 뒤로 전부 미룸**): 공유 카드(도감 달성률+사진 한 장 이미지), 뱃지 도감, 지도 뷰, 친구 도감(초대로 서로 도감 보기·같은 날 같은 암장 "같이 감"), 암장 페이지 크라우드 정보(체크인한 사람만, 가격대·세팅 주기·붐비는 시간), 암장 목록 갱신(사용자 추가·폐업 신고). 평점·댓글은 "N회 이상 방문한 사람만" 규칙으로

## 3. 띠레벨 표
- 자격: 해당 암장 체크인 이력이 있는 사용자만, 암장당 1인 1표(변경 가능)
- 투표 방식: 절대 등급이 아니라 둘 비교("A암장 파랑 vs B암장 파랑 어디가 어렵나")
- 산출: 비교 결과로 순위 → 기준점 몇 개를 V등급에 고정해 표 생성
- 표시: 내부 저장은 V등급 범위, 화면은 사용자가 고른 기준(V·더클 띠 등)
- 전제: 암장마다 띠 구성(순서 있는 라벨 목록, 색이든 글자든)이 있어야 비교가 성립. API·긁기 없음, 체인도 3곳 이상 브랜드 7개·31곳뿐이라 묶기 불가. 체크인한 사람이 직접 입력하는 것만 가능
- 입구 결정(2026-09-29): 비교 투표를 첫 화면으로 두지 않는다. 입구는 **클립에 띠 색 달기**. 그 암장에 띠 구성이 없으면 그때 한 번 "띠 순서 알려줘"로 등록(첫 사람이 만들고 다음 사람이 확인·수정). 띠 구성은 부산물로 쌓이고, 남 없이 내 암장 두세 곳 비교부터 성립
- 초기 데이터: 개발자와 주변 클라이머가 다닌 암장으로 직접 채움. 서울·경기 큰 암장 몇십 곳이면 대부분의 질문에 답이 됨
- 시작 조건: 도감에 체크인 사용자가 생긴 뒤. 홍보도 이 시점부터
- **2026-10-06 재설계(사용자 결정)**. 경쟁 앱 ClimPick(클림픽, 영상마다 날짜·홀드 색·테이프 색·시도·완등을 직접 입력 → 티어·레이팅·피라미드·리포트) 분석 뒤: SNS·세션 기록은 매력 없음(기록은 인스타로 함), 매력적인 건 **암장별 띠색→V 체계**와 랭킹·레이팅. 사용자가 할 일이 많으면 안 됨
  - 순서: (1) 띠색→V 표 — 전국 암장을 미리 조사해 시딩(2026-10-06 조사 착수, 결과 `data/grades*.json` 예정), 빈 암장은 첫 체크인 사용자가 입력, V를 모르는 암장은 체크인한 사용자 투표로 수렴 → (2) 완등 기록 수집 → (3) 랭킹·레이팅은 **사람이 모인 뒤**(후순위, 지금 설계 안 함)
  - 완등 기록: 클립 저장 때 띠 색 한 탭만 추가. 완등 여부는 영상으로 자동 판정(exp-02 하강 직전 최고점 1.5초 정지 규칙)하고 사용자가 고칠 수 있게. 서버엔 **완등한 기록만**(사용자·암장·날짜·띠, 영상은 폰에만). 사용자별 암장별 완등 기록은 나중 랭킹용으로 모아 둠
  - "완등만 찍는 편향"은 문제 삼지 않기로(인스타도 완등만 올림). 기존 '클립에 띠 색 태그 수집' 기각은 이 결정으로 뒤집힘
  - 미정: DB 저장에 로그인이 필요한 문제. 제안은 Supabase 익명 로그인으로 먼저 쌓고 Google 로그인 때 연결. 랭킹 노출 시점에만 로그인 요구
  - 입구를 '클립에 띠 색 달기'로 되돌림(완등 판정 자동 + 한 탭이라 부담 낮음). 비교 투표는 V 모르는 암장의 보조 수단으로 격하
  - **완등 기록 규칙(2026-10-06 오후 확정)**: 구간 분석한 영상은 띠를 골라야 저장. 암장 확정은 (1) 영상 파일의 촬영 위치 → 반경 안 후보 하나면 자동, 여럿이면 저장 전에 고름(체크인 후보 로직 재사용), (2) 위치 없으면 그날 체크인 → 둘 이상이면 촬영 시각에 가까운 쪽을 기본값으로 확인. **둘 다 없으면 암장을 묻지 않고 그냥 저장, 기록 없음**(수동 암장 선택은 안 둠, 랭킹에 못 쓰고 입력만 늚). 기록 한 줄엔 근거 등급(위치/체크인)을 남겨 랭킹 필터로 씀. 날짜로 클립을 암장에 묶던 현재 방식은 폐기
  - 체크인의 역할은 도감 채우기와 투표 자격. 체크인한 유저만 그 암장 띠의 V에 투표. 암장 페이지·비교 뷰에 **V를 표시**(추정 표시·투표 수 함께). 표 없는 암장은 저장 시점에 "띠 순서 알려 주세요"로 첫 방문자가 색 순서만 입력, V는 비워 두고 투표로 채움
  - 시딩 데이터: 커뮤니티 시트 + spiri7(띠 순서와 V 매핑 둘 다 있음, 볼더링 암장 582곳 확인). 수집은 이 세션 권한 분류기가 막아 사용자가 터미널에서 직접 돌림
  - **1단계 구현 뒤 확정(2026-10-06 밤, 사용자 결정)**: 투표·띠 순서 입력·신고는 전부 로그인 필수, 보기만 비로그인 가능. 띠 순서 입력은 표(시드·사용자)가 없는 암장에서만, 투표는 시드가 있어도 칩을 눌러 언제든. V 표시는 시드 추정이 있는 띠는 **10표부터** 투표 중앙값으로 교체(처음 3표였으나 몇 명이 장난치면 뒤집혀서 올림. 가상 표 가중 방식은 복잡해서 기각), 추정 없는 띠는 첫 표부터. 투표 범위는 두 단계(V3~V4)까지, 서버 제약도 같음. **영상 저장 때 띠 색은 순서 유무와 상관없이 필수**(순서 없으면 전체 팔레트에서 고름). 기록은 띠 색으로 저장하므로 나중에 순서가 등록되면 과거 기록이 전부 V로 살아남. 순서 등록·V 투표는 그 뒤 선택으로만 붙임. 영상 위치로 암장이 확정된 사용자도 도감 등록자와 같은 자격(순서 입력·투표)으로 봄(2026-10-06 밤 결정. 서버는 두 경우 다 클라이언트를 믿는 구조라 보안 차이 없음, 완등 기록 행을 먼저 쓰고 그 뒤 순서·투표를 열어 서버가 자격을 확인). 투표 문턱 3표는 사람 모인 뒤 5로 올리는 걸 검토
  - **시드 검증 한계와 신고 채널(2026-10-06 저녁, 사용자 결정)**: 시드 243곳은 출처 간 교차 대조만 했고 최신 기준인지는 확인 불가(spiri7에 날짜 없음, 공식 출처 0건, 사용자가 일일이 확인할 수 없음). 그래서 **표를 그대로 내보내되 틀리면 신고받는다**. 띠 난이도 섹션 아래 "틀렸나요?" 한 줄 → 종류 둘 중 하나(띠 순서·색이 다름 / V 매핑이 다름) + 어느 띠인지(선택) + 한 줄 메모. 서버 테이블 하나(사용자·암장·종류·띠·메모·체크인 이력 여부·시각). 신고는 로그인만 있으면 가능하게 두고 체크인 여부는 줄에 같이 남겨 우선순위에 씀(초기엔 사람이 적어 문턱을 낮춤). 처리는 개발자가 Supabase에서 보고 `grades.json`을 고쳐 재시딩. 같은 암장에 신고가 쌓이면 섹션에 "확인 중" 표시. 투표·수정 제안은 사람이 모인 뒤의 자동 보정, 신고는 그 전의 수동 보정 채널

- 목표: 떨어진 시도 영상을 넣으면 다음 시도에서 붙게 돕는다. 완등 영상도 넣어 비교 기준·라벨로 씀
- 안 만드는 것: 사지별 힘 %, 완등 확률, 확률 기반 다음 홀드 추천. 영상에 없는 정보라 숫자를 지어내게 됨
- 형태: 4층(측정 → 루트 인식 → 같은 문제 완등 시도와 비교 → 코칭 문장). 첫 버전은 1층 + 규칙 + 범용 비전-언어 모델로 **기술 코칭**까지. 베타 수준은 같은 문제의 완등 클립이 모인 뒤(본인 → 서버). 홀드 종류 대신 당기는 방향과 체류 시간을 씀. 판정이 아니라 관찰로 말하고 사용자가 부정할 수 있게. 모델 학습 없음
- 촬영 조건은 삼각대·정적부터. 들고 찍기·다이나믹은 확장
- 서버가 필요해지는 지점은 3층(다른 사용자의 같은 문제 클립). 3단계 띠레벨 표가 아니라 여기가 서버 도입의 첫 이유가 될 수 있음
- 시작 조건: `docs/exp-02-move-analysis.md` 1층 통과
- 규모: 기능이 아니라 연구 과제. 1층만 출시에 넣고 2~3층은 클립이 쌓이면서

## 탈락한 아이디어와 이유
- 시도 분석(동작 코칭): 2D 관절·색으로 보여줄 수 있는 건 클라이머가 이미 아는 것이고, '다음엔 어떤 무브'는 같은 루트 완등 데이터 없이는 추측. 하루 구현 후 폰에서 보고 폐기(exp-02)
- 영상에서 난이도 자동 인식: 국내 볼더링장 난이도는 홀드 색이 아니라 홀드 옆 테이프 색이라 폰 영상으로 못 읽음
- 클립에 띠 색·완등 태그 수집: 개인용은 기각한 세션 로그와 같고, 표용은 완등 영상만 찍는 편향으로 못 믿음
- 사진 앨범 스캔으로 과거 방문 자동 등록: 도감은 앱을 쓴 이유로만 채움
- 동작 분석 중 힘 분포·다음 홀드 추천: 2D 영상에 없는 정보
- 세션 로그: 기록 자체가 부담, 본인도 안 쓸 것
- 행보드 타이머·홀드 마킹·부상 관리: 기존 앱으로 충분
- 파트너 매칭·베타 공유: 사용자 없으면 빈 앱, 한 달 안에 못 모음
- 세팅 교체 일정: 데이터 소스 없음(암장 인스타 수동 이관)
